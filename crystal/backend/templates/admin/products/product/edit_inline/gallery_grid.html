{% load i18n admin_urls static %}{% comment %} Crystal "media grid" inline — a Shopify-style photo card for ProductImage. ── The scaffold is not decoration ───────────────────────────────────────── django/contrib/admin/static/admin/js/inlines.js binds this literally: * it finds the group by ".js-inline-admin-formset" and reads data-inline-type / data-inline-formset off it; * for type "stacked" it selects "#-group .inline-related" as the set of forms — so ONLY real tiles may carry .inline-related, and the headings below deliberately do not; * "Add another" clones "#-empty" and rewrites every id/name/for matching "-(\d+|__prefix__)" — so each tile's id must be "-" with equal to that form's OWN index, which is exactly what {{ inline_admin_form.form.prefix }} already is. Using forloop.counter0 would be wrong here because the tiles are re-ordered into variant groups and no longer come out in formset order; * the add link is injected after the LAST .inline-related, and new tiles are inserted before #-empty — so the empty tile has to be the last .inline-related in the document, which is why the "all sizes" group is rendered last. Get one of those wrong and "Add another" fails silently. ── Grouping without a template tag ──────────────────────────────────────── The forms cannot be pre-sorted (the ModelAdmin orders by ['order', 'id']), and {% templatetag openblock %} dictsort {% templatetag closeblock %} blows up on the None/int mix that a nullable variant FK produces — it swallows the TypeError and returns "", i.e. an empty inline. So the grouping is done by filtering the formset once per variant. N <= 18 images and V <= 8 sizes, so the nested loop is free. ── Thumbnails ───────────────────────────────────────────────────────────── Imported photos are stored as SITE-ROOT-RELATIVE paths ("product-photos/ CL-414/hero.jpg") whose files live on the website service, so ImageField.url gives /media/... which 404s in production. If ProductImage (or the inline) grows a `public_image_url` that runs products.admin._public_url(), this template picks it up automatically; until then it falls back to .url, which is correct locally because MEDIA_ROOT is the site tree. {% endcomment %}
